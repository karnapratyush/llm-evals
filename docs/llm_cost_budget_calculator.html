Default rates reflect each vendor's published API pricing as of October 2026 (Anthropic, OpenAI, Google, xAI, DeepSeek) — edit them before relying on this, since rates change monthly. "Cache write" is the one-time cost of first caching the repeated block; "cache read" is the discounted cost of reusing it on every later call in the same task. Set "LLM calls / task" to 1 to see why caching doesn't help a single-shot call. xAI and DeepSeek don't publish a separate cache-write premium, so their "write" field is set equal to the input price as a simplifying assumption — their real caching is closer to "automatic and free to enable," which only helps your numbers here.

Quality scores are pre-filled from Artificial Analysis's Intelligence Index (artificialanalysis.ai/models) where a clear match existed — they're a general-capability benchmark, not your task, so treat them as a starting point and replace them with your own eval numbers where it matters. Gemini 3.1 Flash-Lite and the brand-new Gemini 4 Argon are left without a score/price respectively since no clean match or public rate existed yet at the time this was built.

The open-weight rows (Kimi, GLM, Qwen, Llama, GPT-OSS) are priced as hosted on Together AI, one of several inference providers for these weights — the same open model is often cheaper or pricier on Fireworks, Groq, OpenRouter, a cloud provider, or self-hosted, and each lab's own first-party API (where one exists, e.g. Moonshot or Z AI direct) usually differs from any third-party host too. There's no single "official" rate for an open-weight model the way there is for a closed one — swap in the numbers for whichever host you'd actually run on. None of these models have a published cache-write premium or a confirmed cache discount on Together, so their cache fields are set equal to the input price, meaning this tool won't show a caching benefit for them until you fill in real numbers from your provider. MiMo-V2.6-Pro, currently Artificial Analysis's top-ranked open-weight model, isn't included — it wasn't available on Together at the time this was built.

The new "Coding 0–100" column is Artificial Analysis's separate Coding Index (distinct from the overall Quality/Intelligence Index). Their own site renders every chart client-side, so there's no static page to pull exact numbers from for most models, and the per-model numbers floating around other comparison sites were inconsistent enough that I didn't trust them the way I didn't trust the pricing aggregators earlier in this chat. I could only confirm scores for four rows — Kimi K2.5, GLM-4.7, Qwen3.5 397B A17B, and GPT-OSS-120B — by cross-checking a secondary source that embeds Artificial Analysis's own data and matching it back to these exact prices. Every other row is left at 0 rather than guessed. If you can open artificialanalysis.ai yourself (it renders fine in a browser, just not for a fetch), the Coding Index numbers for your other candidates are on the model comparison pages — tell me the numbers and I'll drop them in.

Previous-generation rows (Claude Opus 4.1, Claude Sonnet 4.5, Claude Haiku 3.5, Gemini 2.5 Pro, Grok 4.5/4.3/Build 0.1) are still live and billable as of this build and carry verified pricing, but none have a quality score filled in — they'd mostly fallen off the current Artificial Analysis leaderboard snapshot used for the other rows, so fill those in from your own evals if you're comparing across generations. OpenAI is the exception: its older general-purpose line (GPT-4o, GPT-4.1, GPT-4-turbo, o1, o3-mini, o4-mini, GPT-3.5) is being fully shut down on October 23, 2026, with no pricing page listing for it anymore — there's no meaningful "older OpenAI model" left to add here.

Google's context caching also bills a separate hourly storage fee on top of the per-token read price, which isn't modeled here — check ai.google.dev/gemini-api/docs/pricing if a cache is held open for a long time. DeepSeek also runs peak/off-peak pricing (off-peak is half price, 01:00–04:00 and 06:00–10:00 UTC on weekdays excluded) — defaults above use the higher peak rate as the conservative case.
